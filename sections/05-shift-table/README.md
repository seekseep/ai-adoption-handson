# シフト表を作る

2 つめの実習です。**同じ 1 つの課題を、4 通りのやり方で解きます。**

課題は「スタッフの勤務希望と条件から、1 週間のシフト表を組む」。座席表よりも条件が複雑で、
しかも扱うデータが**人の名前と働き方**という、社外に出したくない種類のものです。

## 4 通りのやり方

同じ課題を、データの出ていく量を減らしながら 4 回解きます。

| | やり方 | Codex に渡すもの |
|---|---|---|
| 1 | [データをそのまま使う](./01-raw-data/LECTURE.md) | 名前・勤務希望・条件ぜんぶ |
| 2 | [データを隠して使う](./02-masked-data/LECTURE.md) | 記号に置き換えた勤務希望と条件 |
| 3 | [データを渡さない仕組みを作る](./03-local-logic/LECTURE.md) | 条件の説明だけ（データは渡さない） |
| 4 | [データの行き先を確認する](./04-data-flow/LECTURE.md) | — （確かめる回） |

1 から 3 へ進むにつれて、Codex に渡す情報がどんどん減っていきます。**そして結果の質は落ちません。**
むしろ 3 が一番使えるものになります。そこが体感してほしいところです。

4 では、3 で作ったツールが本当に通信していないことを、ブラウザの開発者ツールで自分の目で
確認します。

## 使うデータ

架空のスタッフ 6 名の勤務希望を使います。1 では「田中」「佐藤」といった架空の名前のまま渡し、
2 では「A さん」「B さん」に置き換えて渡し、3 では渡しません。

:::warning
練習でも、**実際の同僚の名前と勤務希望は使わないでください。** 1 のやり方は
「実データではやらない方法」を体験するための手順です。
:::
