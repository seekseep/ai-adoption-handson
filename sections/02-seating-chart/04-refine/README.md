# 条件を伝えながら座席表を修正する

座席表セクションの 4 つめ（最後）。「あの 2 人は離して」のような後出しの条件に対応する回。

## 動かす

`example/index.html` をダブルクリックすればブラウザで開きます。

## 完成例の中身

```text
04-refine/
├── LECTURE.md
├── README.md
├── images/
└── example/
    ├── index.html    マップ ＋ 席の情報 ＋ 出席 ＋ 条件の4欄
    ├── main.js       席順を何通りか試して、条件を破る数が最小のものを採用する
    └── style.css     条件の成否一覧の見た目
```

完成例の割り当ては「ランダムに何通りか試して一番マシなものを選ぶ」方式（`TRY_COUNT = 400`）。
最適解を出すアルゴリズムではないので、**押すたびに結果が変わる**。これは仕様。

## 講師向けメモ

- ここが座席表セクションの山場。伝えたいのは 2 つ
  1. **条件は後から増える。増えても壊れない形にしておく**（欄を分けてある効果がここで出る）
  2. **どの条件が通ってどれが通らなかったかを画面に出す**。出さないと「直した」と言えない
- 「押すたびに結果が変わる」ことに不安を持つ人がいる。AI の出力と同じで、
  **結果ではなく条件で判定する**という話につなげると、次のセクションの伏線になる
- 矛盾する条件（「離す」と「となり」を同じ2人に）をわざと入れさせると理解が早い
